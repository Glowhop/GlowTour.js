# Documentation

Use this skill when writing or reviewing repository documentation.

## Rules

- Write for the next maintainer who has repository context but not conversation context.
- Keep documentation concise, factual, and current.
- Do not document behavior that is not implemented or accepted.
- Record important decisions when they affect architecture, public interfaces, setup, release, migration, or security.
- Prefer examples only when they reduce ambiguity.

## Output

- State what changed and why it matters.
- Link or name the relevant files when useful.
